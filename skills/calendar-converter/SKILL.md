# 曆法換算 (calendar-converter)

所有東方命理系統的時間基準引擎。**曆法不可心算**,一律執行 script 取得結果。

## 使用方式

```bash
python3 scripts/convert.py --date "1990-08-15 23:15" --tz "Asia/Taipei" --lon 121.56 --lat 25.04
```

參數:
- `--date`:出生地**當地時間** `"YYYY-MM-DD HH:MM"`(不論國家,一律當地時間)
- `--tz`:IANA 時區名(如 `Asia/Taipei`、`America/Los_Angeles`),由出生地判斷;DST 自動處理
- `--lon`:出生地經度(東經正、西經負),用於真太陽時;由出生城市查知名座標即可
- `--lat`:出生地緯度(選填;提供時加算上升星座交界)
- `--no-tst`:略過真太陽時校正(僅在使用者明確要求時使用)

## 核心規則(不可違反)

1. **真太陽時** = 當地標準時 + 經度修正((經度 − 時區中央經線)×4分) + 均時差(NOAA 公式)
2. **子時換日**:真太陽時 ≥ 23:00 即算**次日**的早子時(子時為一日之始)。例:6/2 23:15 出生 → 以 6/3 子時排盤
3. 農曆、四柱、節氣均以**換日後的排盤基準日**計算
4. 輸出中「四柱八字_立春界」供八字用(年柱以立春為界);「年干支_正月初一界」供紫微(本系統預設口徑,見 ziwei/school.json)與民俗生肖用

## 邊界對照(細節判斷依據)

**唯一主軸 = 出生絕對時刻(UTC)**。各系統邊界都由同一時刻以天文計算推出,不互相換算:

| 系統 | 邊界 | 依據 | 警示 / 注意門檻 |
|---|---|---|---|
| 八字 | 年柱 | 立春(太陽黃經 315°) | <24 小時 / <72 小時 |
| 八字 | 月柱 | 節(315°起每 30°) | <24 小時 / <72 小時 |
| 占星 | 太陽換座 | 中氣(0°起每 30°) | <24 小時 / <48 小時 |
| 紫微 | 年界 | 正月初一 | ≤1 天 / ≤3 天 |
| 紫微 | 月界 | 合朔(初一) | <12 小時 / <36 小時 |
| 紫微 | 閏月歸屬 | 閏月 15/16 日 | 落在 15 或 16 日即警示 |
| 紫微/八字 | 時辰 | 真太陽時奇數整點 | <10 分鐘 / <30 分鐘 |
| 占星 | 上升星座 | 上升點度數 | <1° / <3°(約 4 分鐘/度) |

**兩種問題分開看**:

| 類型 | 狀態 | 意義 | 處理 |
|---|---|---|---|
| 時間精度風險 | 警示 / 注意 / 安全 | 出生時刻離**某一個**系統的切點多近;越近,出生時間一點誤差就會換柱/換宮 | 警示:確認出生時間或兩案並看;注意:交接期,參酌前後之氣 |
| 系統口徑差異 | 口徑差異 / 一致 | 出生落在**兩個**系統切點之間,與時間誤差無關 | 兩系統各用各的,**不可為了「一致」而改其中一方**,報告中寫明 |

系統口徑差異的兩列:
- **年界落差區間**:立春與春節每年相差 0~約 20 天,先後順序每年不同。出生在兩者之間 → 八字年柱與紫微生年不同(例:2026 立春 2/4、春節 2/17,2/4~2/16 出生者八字丙午、紫微乙巳;2025 春節 1/29、立春 2/3,1/29~2/2 出生者八字甲辰、紫微乙巳)
- **月份口徑**:八字月依節、紫微月依朔,每個月都有一段錯開,屬結構性差異
- 天文計算用 Swiss Ephemeris;時刻以出生地時區輸出

## 輸出欄位

JSON 包含:真太陽時、時辰、`iztro_time_index`(0-11,直接餵給紫微 skill)、排盤基準陽曆、農曆、閏月、四柱、節氣、生肖、`邊界對照`(主軸、摘要、對照表、口徑提示)。

## 依賴

`lunar-python`、`pyswisseph`(script 會自動安裝;手動:`pip install lunar-python pyswisseph --break-system-packages`)

## 給其他 skill 的介接

紫微 skill 可直接用 `排盤基準陽曆` + `iztro_time_index`,或自帶相同校正邏輯。換算結果如有疑義,以本 skill 為準。
